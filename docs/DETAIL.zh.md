# 回合收口质量门禁

回合结束时跑项目自己的检查，把失败证据交回模型，让回合不会带着红灯收口。

## 设置卡上改的是什么

- **门禁** — `enabled`（默认开）关掉后门禁完全不跑，模型可能带着坏检查收回合。`maxInjectsPerTurn`（1–5，默认 2）限制一个会话跨回合最多收到几次修复指令，这是防失控的闸。`gateBudgetMs`（10000–600000，默认 300000，卡上按秒显示）是整趟门禁的预算：超时按「未能执行」注入，绝不当成通过。
- **记忆反馈** — `memoryFeedback`（默认关）开了才会把失败证据写进记忆网关的 L0 层；教训总线的上报不受这一位影响。`memoryGatewayUrl` 没有随包默认值：留空时回落到环境变量 `TDAI_GATEWAY_URL`，两者都空就是未配置，功能不跑。`memoryGatewayKeyRef`（默认 `TDAI_GATEWAY_KEY`）存的只是凭据**引用名**，密钥留在宿主凭据服务里，不进设置。清空这一格是恢复默认引用名，不是关掉反馈。

这些值每回合现读，改完下一回合生效，不用重启宿主。反馈要真正送出去，需要开关打开、地址能解析出值，并且凭据服务里确实存着引用名指向的那份值。

## 要重启的值

`maxRootDepth`（默认 10，决定从被改文件往上找项目根的最深层数）与 `gateStdoutMaxBytes`（65536）属于部署假定值，刻意不进设置卡：写在本插件注册行的 `config:` 块，改值随重启生效。

还有一条要提前知道：宿主重启后回合游标回到 fork 点，所以重启后的第一个回合会把门禁重跑一遍。

## 需要外部提供什么

门禁命令按项目根现场探测，绝不虚构：该根 `package.json` 声明了 `check` 脚本才用 `pnpm check`，否则依次试 `cargo check`、只有存在 `ruff.toml` 或 `[tool.ruff]` 时才用 `ruff check .`、再否则 `tsc --noEmit`。命令经宿主沙箱执行，所以 `SANDBOX_UNAVAILABLE` 说的是「根本没跑成」，不是「跑过了」。要连记忆网关还得有可达地址与被引用名指向的凭据。
